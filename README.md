# Открытки дня

Сайт собирается сам: каждый день в 00:05 UTC GitHub запускает `build.js`, тот берёт праздники
из открытой базы, выбирает примету дня и публикует готовые страницы. Вручную каждый день делать ничего не нужно.

## Запуск за 15 минут

1. Зарегистрируйтесь на github.com и создайте новый **публичный** репозиторий.
2. Загрузите в него все файлы из этого архива (кнопка «Add file → Upload files»; папку `.github` тоже).
   Основная ветка должна называться `main`.
3. В репозитории: **Settings → Pages → Source: GitHub Actions**.
4. Откройте вкладку **Actions** — сборка запустится сама. Через пару минут сайт появится по адресу
   `https://ВАШ_ЛОГИН.github.io/ИМЯ_РЕПОЗИТОРИЯ/`.
5. Купите домен, подключите его в **Settings → Pages → Custom domain** и впишите адрес в `config.js` (поле `url`).
   Этот адрес печатается на каждой открытке и используется в ссылках «Поделиться».

Проверить у себя на компьютере: `npm install`, затем `node build.js` — сайт появится в папке `dist/`.

## Реклама

Всё в `config.js`, раздел `ads`. На странице три места: под панелью праздников, под открыткой и внизу.

1. Сначала сайт должен поработать и набрать посетителей — рекламные сети (РСЯ, AdSense) пустые сайты не одобряют.
2. После одобрения сеть выдаст код: загрузчик вставьте в `head`, коды блоков — в `slot1`, `slot2`, `slot3`.
3. Строку для `ads.txt` вставьте в `adsTxt`.
4. Поставьте `adPlaceholders: false`, чтобы убрать пунктирные рамки с мест, где кода ещё нет.

Каждый блок подписан словом «Реклама» — это требование закона и рекламных сетей, не убирайте подпись.
Для посетителей из ЕС до подключения AdSense нужен баннер согласия на cookies (его выдаёт сам Google
в настройках AdSense: «Конфиденциальность и сообщения»).

## Что где лежит

| Файл | Что это |
|---|---|
| `config.js` | Адрес и название сайта, реклама |
| `data/facts.js` | Приметы. Новые дописывайте в конец |
| `data/greetings.js` | Поздравления на открытках по датам |
| `data/translations.js` | Какие праздники показывать и как они называются по-русски и по-немецки |
| `data/countries.js` | Список стран |
| `photos/` | Фотографии для открыток (см. `photos/ИСТОЧНИКИ.txt`) |
| `src/` | Внешний вид и код страниц |
| `build.js` | Сборщик |

## Фотографии для открыток

Загрузите фото в папку `photos/` (на GitHub: открыть папку → Add file → Upload files).
Через пару минут сайт пересоберётся, и открытки станут фотографическими. Пока фото нет,
открытки рисуются с цветами-эмодзи.

Только свободные лицензии: Pixabay, Pexels, Unsplash. Картинки из поиска и с сайтов открыток
брать нельзя — у них есть авторы.

## Открытки от нейросети (бесплатно)

Каждую ночь сайт может рисовать 6 новых открыток нейросетью FLUX.1 [schnell] через Cloudflare Workers AI.
Бесплатный лимит Cloudflare — 10 000 «нейронов» в день, 6 картинок тратят около 350. Платить ничего не нужно:
на бесплатном тарифе сверх лимита запросы просто не выполняются, счёт не придёт.

1. Зарегистрируйтесь на dash.cloudflare.com (бесплатно, карта не нужна).
2. Скопируйте **Account ID** (на главной странице аккаунта справа или в адресной строке).
3. **My Profile → API Tokens → Create Token → Create Custom Token**: права **Account → Workers AI → Read**
   (или готовый шаблон «Workers AI»). Скопируйте токен — он показывается один раз.
4. В репозитории на GitHub: **Settings → Secrets and variables → Actions → New repository secret**:
   `CF_ACCOUNT_ID` = Account ID, `CF_API_TOKEN` = токен.
5. **Actions → Сборка и публикация сайта → Run workflow**. В журнале появится «Нейросеть: нарисовано 6 из 6».

Какие картинки рисовать — в `data/prompts.js` (по-английски, с привязкой к месяцам). Надписи нейросеть не пишет,
их накладывает сайт. Если ключей нет или нейросеть не ответила, сайт берёт фото из `photos/`.

## Своя открытка

На странице есть раздел «Своя открытка»: человек пишет или диктует голосом, кому и что пожелать,
и текст появляется на выбранной открытке. Всё происходит в телефоне посетителя — бесплатно и без ограничений.
Кнопка микрофона показывается только там, где браузер умеет распознавать речь (Chrome, Android, новые iPhone).

## Важно знать

- **Приметы нужно проверить.** В `data/facts.js` у каждой записи есть `ok: true/false`. Сейчас проверены по
  источнику только три, остальные записаны по памяти. Проверьте запись по источнику из поля `src`,
  поставьте `ok: true`. С `onlyCheckedFacts: true` в `config.js` на сайт попадут только проверенные.
- **Праздник попадает на сайт, только если у него есть перевод** в `data/translations.js`. Сборка печатает
  список пропущенных. Траурные и политические даты пропущены намеренно.
- **Даты исламских праздников расчётные** и могут отличаться от объявленных на день.
- **Китая и Южной Кореи в праздниках нет:** библиотека падает на расчёте их лунного календаря.
- **GitHub отключает расписание, если в репозитории 60 дней не было изменений.** Придёт письмо — нажмите в нём
  кнопку продления или внесите любую правку. Если сборка всё же остановится, сайт продолжит показывать
  правильный день: данные собраны на год вперёд, а день выбирается в браузере.
- **Данные о праздниках** — библиотека date-holidays, лицензия CC BY-SA 4.0. Ссылка на неё стоит внизу каждой страницы,
  её нужно оставить.
- Шрифты лежат на самом сайте, а не загружаются с Google — так нет претензий по GDPR в Германии.
